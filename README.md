# JIRA Project Analytics

Программа загружает задачи проекта JIRA Server/Data Center и формирует автономный HTML-отчёт с шестью видами аналитики. Для взаимодействия с JIRA используется **Jira Python Library** (`jira`, проект [pycontribs/jira](https://github.com/pycontribs/jira)); приложение не формирует HTTP-запросы к REST API самостоятельно.

По умолчанию используется публичный Apache JIRA и проект `KAFKA`. Другой проект и дополнительные условия можно задать в `config.json`.

## Что строится

1. **Время жизни закрытой задачи** — гистограмма дней между созданием и закрытием.
2. **Время в каждом состоянии** — отдельная гистограмма для каждого найденного состояния; повторные периоды в одном статусе суммируются.
3. **Созданные и закрытые задачи по дням** — дневные значения и накопительные итоги.
4. **Топ-30 пользователей** — задачи, где пользователь исполнитель, репортёр, а также число уникальных связанных задач.
5. **Залогированное время** — гистограмма `timespent` для закрытых задач.
6. **Количество задач по серьёзности** — по полю `priority` по умолчанию; для поля `Severity` задайте его ID в `severity_field`.

HTML содержит Plotly.js внутри себя и может открываться локально в браузере после формирования отчёта.

## Работа с Jira Python Library

`libs/utils/client.py` адаптирует библиотеку `jira` к формату данных, который ожидают аналитические функции:

- `JIRA.search_issues(..., json_result=True, use_post=True)` — поиск задач через POST-вариант JQL Search. `startAt` и `maxResults` передаются явно, чтобы сохранить контролируемую пагинацию и настройку `max_issues`.
- `JIRA.issue(issue_key, fields=..., expand="changelog")` — получение задачи и доступной истории изменений.
- `JIRA.fields()` — получение ID и названий полей.
- Тайм-аут и количество повторных запросов передаются в конструктор клиента Jira Python Library.
- Basic Auth передаётся через `basic_auth`, Bearer-токен — через `token_auth`.

Для сохранения параллельной загрузки истории отдельный клиент Jira Python Library создаётся для каждого потока. Адаптер возвращает обычные словари, поэтому `analytics.py` и `charts.py` продолжают работать с тем же форматом данных.

Документация библиотеки: https://jira.readthedocs.io/ .

## Требования

- Python 3.10 или новее.
- Доступ к REST API JIRA и право просмотра выбранного проекта.
- Пакет `jira` (Jira Python Library), `requests` для нормализации сетевых исключений и `plotly` для графиков.

## Запуск на Windows

1. Установите Python 3.10+ и убедитесь, что команда `py` доступна.
2. Распакуйте проект.
3. Проверьте параметры в `config.json`.
4. Запустите `config\\autorun.bat`.
5. Откройте созданный HTML в каталоге, заданном `output_dir`; при настройке по умолчанию это `output\\jira-analytics-kafka.html`.

Сценарий установит зависимости из `requirements.txt` и запустит `libs/main.py`. Если `config.json` отсутствует, скрипт скопирует `config.example.json` в `config.json` и завершится — проверьте настройки и запустите его повторно.

## Запуск на Linux

Из корня проекта:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python libs/main.py --config config.json
```

Или запустите `config/autorun.sh`. Для установки библиотек нужен доступ к PyPI либо предварительно подготовленный кэш pip.

Можно использовать консольную команду после установки проекта:

```bash
python -m pip install -e .
jira-analytics --config config.json
```

## Конфигурация

Основные параметры `config.json`:

- `base_url` — URL сервера, например `https://issues.apache.org/jira`.
- `api_version` — поддерживается `2` для Jira Server/Data Center.
- `project_key` — ключ проекта, например `KAFKA` или `HDFS`.
- `jql_filter` — дополнительное условие JQL без ключевого условия проекта и без `ORDER BY`.
- `severity_field` — ID поля серьёзности, например `priority` или `customfield_12345`.
- `page_size` — желаемый размер страницы.
- `max_issues` — `0` означает загрузить все доступные задачи; положительное значение ограничивает выборку.
- `workers` — число потоков загрузки истории.
- `auth_mode` — `anonymous`, `basic` или `bearer`.

Для Basic Auth задайте `JIRA_USERNAME` и `JIRA_API_TOKEN` (или `JIRA_PASSWORD`) в переменных окружения. Для Bearer Auth задайте `JIRA_BEARER_TOKEN`. Секреты не записываются в JSON-файл. Переменные `JIRA_BASE_URL`, `JIRA_PROJECT_KEY` и `JIRA_AUTH_MODE` могут переопределять настройки файла.

## Сборка дистрибутива

Из корня проекта:

```bash
python config/build.py
```

Будет создан `dist/jira-analytics-1.1.0.zip`. В дистрибутиве присутствуют приложение, конфигурация, зависимости, README и скрипты запуска для Windows/Linux.

## Автоматические тесты

```bash
python -m pip install pytest
python -m pytest -q
```

Тесты используют имитацию интерфейса JIRA и не требуют подключения к удалённому серверу. Они проверяют расчёты, вызовы методов адаптера Jira Python Library, пагинацию, генерацию HTML и сборку дистрибутива.

## Архитектура

- `libs/utils/config.py` — загрузка и проверка параметров.
- `libs/utils/client.py` — адаптер Jira Python Library, пагинация, авторизация и обработка ошибок.
- `libs/utils/analytics.py` — расчёт аналитических данных.
- `libs/utils/charts.py` — построение графиков и HTML-отчёта.
- `libs/utils/cli.py` — управление последовательностью работы программы, параллельная загрузка истории, сводка и предупреждения.
- `libs/tests/` — unit- и интеграционные тесты.
- `config/build.py` — сборка ZIP-дистрибутива.

## Ограничения

- `resolutiondate` — основной источник даты закрытия; поле `updated` не используется вместо даты закрытия.
- `timespent` — зарегистрированное рабочее время, а не календарная длительность задачи.
- Если Jira возвращает неполный changelog, программа формирует предупреждение; длительность по неполной истории нельзя считать точной.
- Графики строятся по задачам, доступным текущей учётной записи и удовлетворяющим JQL. Сравните результат с фильтрами и стандартными визуализациями JIRA.
- Автоматические тесты не заменяют проверку подключения к реальному серверу JIRA.
